# 单旋钮质量感知边缘卸载修改方案

## 核心意思

在当前 `FDEdge-main` v5 项目上新增一个质量感知版本，不直接照搬 LAB 的图像降级场景，也不采用三维偏好向量。新的核心是：

```text
single-knob quality-aware edge offloading
```

也就是只给用户一个偏好旋钮 `omega_q`：

```text
omega_q 越小：更偏向低资源开销，即低 delay / low energy
omega_q 越大：更偏向高 accuracy
```

底层仍然记录三个指标：

```text
delay / energy / accuracy
```

但状态里只放一个 `omega_q`，不是 `omega_T, omega_E, omega_A` 三个权重。论文里不要声称覆盖完整三维 Pareto frontier，而应表述为：

```text
single-knob resource-quality trade-off curve
```

## 新故事线

不要做 LAB 的图像降级。新场景建议使用模型侧质量控制：

```text
early-exit edge inference
```

通俗故事是：

边缘 AI 任务不一定每个样本都要完整跑完整个神经网络。简单样本可以在浅层 early exit，节省 delay 和 energy；困难样本需要跑到更深层，甚至 final exit，以保证 accuracy。现有 edge offloading 方法大多只优化 delay 和 energy，而质量感知系统通常依赖固定标量 reward。新方法引入单个质量偏好 `omega_q`，联合选择卸载服务器和 early-exit level，在资源开销和任务精度之间形成一条可调 trade-off curve。

当前 v5：

```text
state  = task + omega_T + omega_E + server states
action = server
reward = (-delay, -energy)
```

新版本：

```text
state      = task + omega_q + difficulty + server states
action     = server x exit_level
reward_vec = (-delay, -energy, +accuracy)
```

## 1. 新环境 mofd_environment_quality.py

从 `mofd_environment.py` 复制结构，新增环境类：

```python
class MOFDQualityEnvironment:
```

关键变化：

```python
N_OBJ = 3
action_dim = Emax * n_quality_levels
```

动作解码：

```python
server_id = action // n_quality_levels
exit_level = action % n_quality_levels
```

状态头部保持 4 维，便于兼容现有 actor 风格：

```text
state_head = [
    task_size_norm,
    task_work_norm,
    omega_q,
    difficulty
]
```

后面继续拼接每个 server 的特征。`difficulty` 第一版可以用随机值 `[0, 1]` 模拟任务难度，后续真实实验可替换为 early-exit 第一层 confidence / entropy。

`sample_context()` 只采样一个 `omega_q`：

```python
if fixed_omega is None:
    omega_q = rng.uniform(0, 1)
else:
    omega_q = float(fixed_omega)
```

`step()` 返回：

```python
r_vec, delay, energy, accuracy, server_id, exit_level
```

奖励向量：

```python
r_vec = np.array([
    -delay * delay_scale,
    -energy * energy_scale,
    accuracy * accuracy_scale,
], dtype=np.float32)
```

## 2. 新建 quality_profiles.py

第一版只做 2 个 early-exit 档位，避免复杂度爆炸：

```python
QUALITY_PROFILES = [
    {
        "name": "early_exit",
        "cycle_mult": 0.45,
        "energy_mult": 0.45,
        "acc_base": 0.78,
        "difficulty_sensitivity": 0.12,
    },
    {
        "name": "final_exit",
        "cycle_mult": 1.00,
        "energy_mult": 1.00,
        "acc_base": 0.90,
        "difficulty_sensitivity": 0.05,
    },
]
```

这些数值只作为 synthetic profile，不要在论文中当真实实验数值。真实实验后再用 CSV profile 替换。

accuracy 计算：

```python
accuracy = acc_base - difficulty_sensitivity * difficulty
accuracy = np.clip(accuracy, 0.0, 1.0)
```

delay / energy 计算时，用 profile 调整原始计算量：

```python
effective_cycles = original_cycles * cycle_mult
compute_energy = original_compute_energy * energy_mult
```

因为这是 early-exit 场景，第一版传输数据大小可以不变，主要变化来自模型推理计算量。

## 3. 新建 mofd_model_quality.py

从 `mofd_model.py` 复制必要结构，新增：

```python
class PCPolicyNetQuality(nn.Module)
```

区别是输出维度从 `Emax` 变为：

```python
action_dim = Emax * n_quality_levels
```

如果继续使用 `FeedbackDiffusion`，latent `x`、prior、mask 的维度也要变成 `action_dim`。

server mask 扩展为 action mask：

```python
action_mask = np.repeat(server_mask, n_quality_levels)
```

prior 从 `[Emax]` 扩展为 `[Emax * n_quality_levels]`：

```python
prior_action[server * n_quality_levels + level] = prior_server[server] / n_quality_levels
```

第一版不需要复杂的 quality prior，质量档位均匀即可。

## 4. 新建 mofd_v5_quality.py

从 `mofd_v5.py` 复制 v5 agent，修改为三通道 vector Q，但只使用单个 `omega_q` 标量化。

关键常量：

```python
N_OBJ = 3
OMEGA_Q_INDEX = 2
```

critic 输出：

```python
q_vec: [B, action_dim, 3]
```

三个通道含义：

```text
Q_delay    = delay reward channel, negative
Q_energy   = energy reward channel, negative
Q_accuracy = accuracy reward channel, positive
```

新增固定资源权重：

```python
beta_delay = 0.5
beta_energy = 0.5
```

标量化函数：

```python
def _scalarize_q(self, q_vec, omega_q):
    if omega_q.dim() == 1:
        omega_q = omega_q.unsqueeze(-1)

    resource_q = self.beta_delay * q_vec[..., 0] + self.beta_energy * q_vec[..., 1]
    quality_q = q_vec[..., 2]

    q_eff = (1.0 - omega_q) * resource_q + omega_q * quality_q
    return q_eff
```

含义：

```text
omega_q = 0 -> 主要优化 delay / energy
omega_q = 1 -> 主要优化 accuracy
```

PopArt-lite 可以保留，但 `N_OBJ` 要从 2 改为 3。COR 也可保留，优先保证 shape 正确。

replay buffer 中的 reward 存三维：

```python
r_vec.shape == (3,)
```

target value 从 `[B, 2]` 改为 `[B, 3]`。

## 6. 新建 compare_hv_quality.py

评价时不要写完整三目标 Pareto frontier，而写：

```text
single-knob resource-quality trade-off curve
```

仍可计算 3D HV，点格式：

```python
cost_points = np.stack([
    delay,
    energy,
    1.0 - accuracy,
], axis=1)
```

reference point 建议固定并写入 summary，避免不同方法使用不同 reference point。

至少画四张图：

```text
omega_q vs delay
omega_q vs energy
omega_q vs accuracy
omega_q vs average exit level
```

其中 `omega_q vs average exit level` 很关键。如果 `omega_q` 增大时平均 exit level 上升，说明策略确实在响应质量偏好。

## 7. Baseline 设计

第一版至少实现：


## 8. Sanity checks

请加入这些断言：

```python
assert env.action_dim == env.Emax * env.n_quality_levels
assert len(action_mask) == env.action_dim
assert r_vec.shape == (3,)
assert q_vec.shape[-1] == 3
```

跑 1-2 个 epoch 后，检查 CSV 是否包含：

```text

```

预期趋势：

```text
omega_q 增大 -> accuracy 上升
omega_q 增大 -> avg_exit_level 上升
omega_q 增大 -> delay / energy 可能上升
```

不要求严格单调，但整体趋势应成立。

## 9. 论文贡献点

建议写成：

```text
1. 提出 single-knob quality-aware edge offloading，把用户偏好简化为一个质量旋钮 omega_q。
2. 把动作从 server selection 扩展为 server x early-exit level，实现模型侧质量控制，而不是 LAB 的图像降级。
3. 使用 vector Q 同时建模 delay / energy / accuracy，但用单 omega_q 进行 resource-quality scalarization。
4. 通过偏好响应、3D HV、exit-level 行为分析和消融实验验证方法。
```

注意措辞：

```text
不要说 full three-objective Pareto frontier。
要说 single-knob resource-quality trade-off curve。
```

这样既严谨，也比三维 omega 更简洁。
