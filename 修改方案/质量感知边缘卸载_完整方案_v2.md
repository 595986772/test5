## 0. 背景与现有系统（reviewer 必读上下文）

**现有项目 FDEdge / MOFD-V5**：一个多目标、偏好条件化的边缘计算卸载强化学习系统。

- **场景**：每个时隙到达若干 AI 任务，需决定把每个任务卸载到哪台边缘服务器（Emax 台）。
- **现有目标**：2 个 —— 延迟 delay、能耗 energy。
- **偏好机制**：用户给一个偏好向量 ω=(ω_T, ω_E)（更看重省时间还是省电），系统据此标量化奖励。
- **核心方法（PC-FDN / V5）**：
  - actor = 反馈扩散策略（FeedbackDiffusion，DDPM 式多步去噪生成动作分布）；
  - critic = **向量 Q** `Q(s,a) ∈ R^{N_OBJ}`，逐目标输出，再用 ω 加权标量化；
  - 额外机制：COR（目标间冲突正则，COLA 风格）、PopArt-lite（逐目标量级归一）、H-MCSS（feedback/prior/random 三源候选 + Critic 选优）。
  - **单策略覆盖整条偏好谱**：一个策略对所有 ω 都给出合理分配，扫 ω 即得 Pareto 前沿。
- **状态布局**：`[d_n, ρ·d_n, ω_T, ω_E, (f_e, queue_e, valid_e, gain_e) for e in Emax]`。
- **奖励**：`r_vec=(r_T, r_E)=(-delay, -energy)`，按 `ω·α` 标量化。
- **现状**：2 目标版已能跑通，PC-FDN 的 HV 优于 LDQN / DiscreteSAC 基线（单 seed）。

**本方案要做的扩展**：把目标从 2 个扩成 **3 个（delay-energy-accuracy）**，但用户偏好**不**扩成三维权重，而是**简化为单个质量旋钮 omega_q**；精度来自"模型质量档位"。

**一段失败教训（必须让 reviewer 知道，避免重蹈）**：早先尝试用 **图像降分辨率** 当精度旋钮，结果两个问题叠加——(1) 降分辨率只改"传输比特"，而本环境传输延迟占比小，旋钮被淹没；(2) 环境 `num_tasks_max=50` 队列饱和，延迟飙到 20–100s（远离真实边缘的亚秒级）。诊断结论：环境必须减负载，且精度机制要作用在"主导成本项"上。**本方案据此改用"模型档位"（改计算量，不改传输）+ 减小环境负载。**

## 1. 核心思路

**single-knob quality-aware edge offloading（单旋钮质量感知边缘卸载）**

给用户一个旋钮 `omega_q ∈ [0,1]`：
```
omega_q 越小 → 越偏向省资源（低 delay / 低 energy）
omega_q 越大 → 越偏向高 accuracy
```

| 维度 | 现有 V5 | 本方案 |
|---|---|---|
| 动作 | server | **server × quality_level** |
| 状态头 | [size, work, ω_T, ω_E] | [size, work, **omega_q, difficulty**] |
| 奖励 | (-delay, -energy) | (-delay, -energy, **+accuracy**) |
| 标量化 | ω·α 加权 | **(1-omega_q)·resource + omega_q·quality** |

其中 `resource = β_T·Q_delay + β_E·Q_energy`（固定 β_T=β_E=0.5），`quality = Q_accuracy`。

**质量档位 = 真实模型变体**：浅/小模型（快、省、糙）↔ 深/大模型（慢、费、准）。第一版每个档对应一个真实模型规模（YOLO 变体 / Qwen 尺寸），用公开 benchmark 标定其精度与计算量。

**这是 single-knob resource-quality trade-off curve，不是完整三维 Pareto 曲面**（论文措辞必须如此，见 §8）。

### 2.3 转换为 profile 的规则

每档 profile：`{name, cycle_mult, energy_mult, acc_base, difficulty_sensitivity}`
- `cycle_mult = energy_mult =` 该档 compute / 所选档位中最重者的 compute（compute = FLOPs[检测] 或 params[LLM]，作为 compute 代理）；
- `acc_base =` 易任务精度；
- `difficulty_sensitivity = acc_easy − acc_hard`，使 `acc(difficulty) = acc_base − sensitivity·difficulty`。
  - **LLM**：易=MMLU、难=MATH（小模型在难任务上崩得更狠 → "难任务该用大模型"有真实数据支撑）；
  - **检测**：官方仅给总 mAP → 第一版 `difficulty_sensitivity=0`（占位）；真实化时换成 COCO 的 **mAP_large（易）/ mAP_small（难）**（`model.val()` 自动输出）。

### 2.4 诚实边界（写论文务必照此）
- acc / FLOPs / params / 延迟 = **公开 benchmark 原值**，属 *"calibrated from published benchmarks"*，**不得写成"我们部署实测"**（除非真在设备上跑了 val/inference）；
- `cycle_mult/energy_mult` 是 FLOPs/params 的 **compute 代理**，非实测能耗；
- `difficulty_sensitivity` 中 LLM 部分有数据支撑，检测部分第一版是占位/建模量，需注明。

## 3. 系统改动（基于 V5，并行新建，不动原文件）

新增文件：`mofd_environment_quality.py` / `mofd_model_quality.py` / `mofd_v5_quality.py` / `mofd_quality_main.py` / `compare_hv_quality.py` /（已建）`quality_profiles.py`。

### 3.1 环境 `mofd_environment_quality.py`
- `action_dim = Emax × n_quality_levels`；解码 `server = a // L`，`level = a % L`。
- 状态头 4 维：`[size, work, omega_q, difficulty]`（保持 4 维以兼容现有 actor 的 `task_pref_dim=4`）。
- `step()` 返回 `(r_vec, delay, energy, accuracy, server, level)`，其中：
  - `effective_cycles = ρ·d · cycle_mult[level]` → 进 `comp_delay`、`wait_delay`、`e_exe`；
  - `accuracy = profile.accuracy(level, difficulty)`；
  - `r_vec = (-delay·delay_scale, -energy·energy_scale, accuracy·accuracy_scale)`。
- **关键参数**：`num_tasks_max=10`（**不要继承 50**，避免队列饱和），其余沿用现有物理。

> 物理依据（已核算现有环境，默认参数、空队列）：计算量 ρ·d **主导了延迟的 ~78% 和能耗的 ~99%**（comp_delay≈0.2s vs tran_delay≈0.056s；e_exe≈3.1J vs e_off≈0.03J）。因此 `cycle_mult` 能真正拉开 delay 与 energy —— 这正是"图像降分辨率"做不到、而"模型档位"能做到的根本原因。

### 3.2 Agent `mofd_v5_quality.py`
- `N_OBJ = 3`；critic 输出 `[B, action_dim, 3]`：`(Q_delay, Q_energy, Q_accuracy)`。
- 新标量化：
  ```python
  resource_q = β_T*q[...,0] + β_E*q[...,1]      # β_T=β_E=0.5
  quality_q  = q[...,2]
  q_eff = (1-omega_q)*resource_q + omega_q*quality_q
  ```
- **OMEGA 触点全部从"2 维 slice [2:4]"改为"单 index 2"**：`take_action` 的 `omega_rep`、`update` 的 `omega_b`、actor 更新、**COR 的 relabel（原写 [2:4] 会覆盖 difficulty，必须只写 index 2）**。
- PopArt：`N_OBJ` 2→3（保留）。
- COR：**第一版先关**（`use_cor=False`），其 ω 采样 `dirichlet([1,1])` 与 relabel 都需改单 omega_q；主干跑通后再加回。
- replay buffer 的 reward 存 3 维；target value `[B,3]`。

### 3.3 模型 `mofd_model_quality.py`
- `PCPolicyNetQuality` 输出维度 Emax → `action_dim`；若沿用 FeedbackDiffusion，latent `x` / prior / mask 维度同步改为 `action_dim`。
- `action_mask = np.repeat(server_mask, n_quality_levels)`；prior 均匀展开到 `action_dim`。

## 4. 训练流程

0. 选域（detection=YOLO / llm=Qwen）→ 加载对应 profile。
1. 每轮随机采 `omega_q∈[0,1]` + 一批任务（各带随机 difficulty）；
2. agent 对每个任务输出 (server, level)；
3. 环境查 profile 算 (delay, energy, accuracy)，按 omega_q 标量化为奖励；
4. agent 更新（vector-Q + SAC-α + [PopArt]）；
5. 重复 → 单策略覆盖所有 omega_q。

配置建议（第一版）：`Emax=6, n_quality_levels=2~3, num_tasks_max=10, num_epochs=50, seeds=[0,1,2], β_T=β_E=0.5, accuracy_scale 待标定（见 §9）`。

## 8. 论文故事线与贡献

**痛点**：现有边缘卸载只优化 delay/energy，忽略"精度也可换"；而现代边缘 AI（检测、LLM）天生有"质量档位"（小/浅模型 vs 大/深模型）。无人将"精度档位选择 + 卸载"联合，并用单旋钮让用户调。

**方法**：单旋钮 omega_q 条件化的单策略，联合决定 (卸载目标, 质量档)，一次性学会整条"资源-精度"权衡曲线。

**贡献**：
1. 提出 single-knob quality-aware edge offloading，用户偏好简化为一个质量旋钮；
2. 动作 server → server×quality_level，实现**模型侧质量控制**（非图像降级）；
3. 向量 Q 同时建模 delay/energy/accuracy，但用单 omega_q 做 resource-quality 标量化；
4. 偏好响应 + 3D HV + 档位行为分析 + 消融验证；**在检测(YOLO)与 LLM(Qwen)两类真实负载上各验一遍**。

**诚实定位**：写 "single-knob resource-quality trade-off curve"，**不写** "full three-objective Pareto frontier"；精度 "calibrated from published benchmarks"。

## 9. 已识别的风险与对策（请 reviewer 重点关注）

| # | 风险 | 对策 |
|---|---|---|
| R1 | 环境队列饱和（沿用 num_tasks_max=50）→ 延迟非线性、旋钮失效，重演阶段0 | 强制 `num_tasks_max=10`，让 comp 主导延迟 |
| R2 | 检测侧 difficulty 无效（仅总 mAP）→ "难样本走大模型"讲不出来 | 换 COCO `mAP_large/small` 作 easy/hard（LLM 用 MMLU/MATH，已有真实斜率） |
| R3 | OMEGA 触点漏改 / COR relabel 覆盖 difficulty | 全触点改单 index 2；加断言；COR v1 先关 |
| R4 | accuracy 通道 spread 小（如 Qwen MMLU 0.475→0.861，或精度档差仅 0.1）→ 中间 omega_q 时被 resource 项压住，曲线在 omega_q≈1 才突变、不平滑 | 标定 `accuracy_scale`（如 5~10）使 accuracy 奖励 spread 与 resource spread 可比；用 spread/mean + Spearman ρ(omega_q, acc) 验收 |
| R5 | LLM compute 阶梯过陡（0.5B 仅 72B 的 0.7%）→ 资源代价近乎可忽略、曲线极陡 | 档位选中段（如 1.5B/7B/14B），别用极端两端 |
| R6 | novelty 偏增量（resource+quality 实质仍 2 轴 vs GMORL 的 2 轴，新点是 early-exit/档位×卸载联合） | 诚实定位，靠"单旋钮 + 模型档位 + 双负载泛化"的组合站住；实验须真实 |

## 10. 请 Reviewer（GPT）重点回答的问题

1. **故事/定位**：把 (ω_T,ω_E) 两维偏好换成"resource(固定β) vs quality"的单旋钮，是否削弱了相对 GMORL（已做 delay-energy 2 目标）的贡献？"single-knob + 模型档位 + 双负载"这个组合，够不够一篇 SCI/会议的增量贡献？如何强化 framing？
2. **机制合理性**：用"模型规模档位/early-exit"作 accuracy 旋钮、且 accuracy 只进环境（agent 不真跑模型），这种"用公开 benchmark 标定的合成环境"在审稿人眼里是否可接受？需要至少做几分真实部署/实测才稳？
3. **scalarization 设计**：`(1-ω_q)·resource + ω_q·quality` 且 `resource=0.5·delay+0.5·energy` 固定，是否过简？是否该让 delay/energy 也可调（回到更高维偏好）？固定 β 的代价与收益？
4. **R4/R5（关键工程风险）**：accuracy 通道标定与 compute 阶梯过陡，会不会导致 trade-off 曲线退化为"近乎阶跃"？有没有更稳的标定/选档策略建议？
5. **评估充分性**：四图 + 3D HV + 双负载 + 消融，是否足以支撑结论？还缺什么实验（如真实硬件延迟/能耗、与 MoD/LayerSkip 等 early-exit SOTA 的对照）？
6. **诚实边界**：当前"两种实验=两套公开标定 profile 跑同一仿真器"的表述，是否有过度宣称风险？怎么措辞最稳？
