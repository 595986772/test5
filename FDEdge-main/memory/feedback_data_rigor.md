引用实验数据时必须**先打开文件精确读数再下结论**，不能凭印象/记忆给出"19 个点堆在 [3.95, 3.97]"这种具体数字。提出验收线、问题严重程度判断、改造优先级时同理：每一个具体数字（spread、跨度、相关系数、计数）都必须能追溯到刚才读过的某个 CSV 行或某个工具输出，否则不写。

**Why:** 2026-05-14 在分析 `mofd_pareto_aggregated.csv` 时，我说"19 个点堆在 energy ∈ [3.95, 3.97]、跨度 0.02 J、delay 跨度 0.5 s"——实际是 11 个点扎堆、energy 总跨度 1.0 J、delay 总跨度 71.3 s，差几十倍。用户在 SCI 投稿场景下用这些数字判断 C1 是否成立、改造优先级、验收线——错的数字会把方向带偏几个量级。用户明确反馈"以后一定要严谨 基于事实分析"。

**How to apply:**
- 一旦要在回答里出现"X 个点"、"跨度 Y"、"占比 Z%"、"差 N 倍"这类具体数字，**先 Read/Grep 一次原始文件**，把数字直接复制出来，不要凭印象；
- 如果几轮前已读过的数据，回答前**再读一遍核对**，不要相信自己的短期记忆——特别是当数据被用来支撑某个判断时；
- 写"验收标准 / 通过线 / 量化指标"前，必须先把 baseline 的实际值算出来，否则验收线就是悬空的；
- "塌陷"、"严重退化"、"几乎不变"这类形容词在数字面前要让步——如果数字显示 spread = 1.0 J / mean = 3.8 J ≈ 26%，那不能叫"塌陷"，要叫"延迟主导侧扎堆"；
- 承认错误时直接说错在哪、错了多少倍、影响是什么，不要含糊带过。
